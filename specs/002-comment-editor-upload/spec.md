# 功能規格書：社群留言編輯工具（檔案上傳版）

**Feature Branch**: `002-comment-editor-upload`  
**Created**: 2025-11-19  
**Status**: Draft  
**原始版本**: 001-social-comment-scraper（API 爬取版）改為檔案上傳版，移除 API 依賴

**核心變更**: 從「自動爬取」改為「手動上傳」，提供更簡單、立即可用的解決方案，無需 Meta API 審核

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 上傳留言資料 (Priority: P1) 🎯 MVP

操作人員已從社群平台手動收集留言資料（或使用瀏覽器複製貼上），需要將這些資料匯入工具進行整理和分析。使用者可透過上傳 CSV、Excel 或 JSON 檔案，或直接貼上資料，快速將留言匯入系統。

**為何優先**: 這是整個工具的資料來源，沒有這個功能就無法進行任何後續資料處理。檔案上傳比 API 爬取更簡單、更快速、無需審核，且使用者完全控制資料來源。

**Independent Test**: 使用者上傳一個包含留言資料的 CSV 檔案，驗證系統能正確解析並顯示所有留言在表格中，即代表功能完整可用。

**Acceptance Scenarios**:

1. **Given** 使用者在首頁，**When** 點擊「上傳檔案」並選擇一個 CSV 檔案（包含留言者、內容、時間），**Then** 系統顯示上傳進度並在完成後將所有留言顯示在表格中
2. **Given** 使用者在首頁，**When** 點擊「上傳檔案」並選擇一個 Excel 檔案（.xlsx），**Then** 系統自動解析 Excel 欄位並正確對應到留言、時間、按讚數等欄位
3. **Given** 使用者在首頁，**When** 點擊「貼上資料」並在文字框中貼上 JSON 格式的留言陣列，點擊「匯入」，**Then** 系統解析 JSON 並顯示所有留言
4. **Given** 使用者上傳格式錯誤的檔案，**When** 系統無法解析，**Then** 顯示明確錯誤訊息「檔案格式不正確，請確認為 CSV、Excel 或 JSON 格式，並包含必要欄位（留言者、留言內容）」
5. **Given** 使用者上傳大檔案（>5MB 或 >10,000 則留言），**When** 系統開始解析，**Then** 顯示「資料量較大，正在處理中...」進度指示器，並在完成後顯示摘要「已匯入 X 則留言」

---

### User Story 2 - 使用範例資料快速體驗 (Priority: P2)

首次使用者或想快速體驗功能的使用者，可以點擊「載入範例資料」立即看到工具的所有功能，無需準備任何檔案。

**為何優先**: 降低使用門檻，讓使用者能立即體驗所有功能，了解工具價值後再投入時間準備真實資料。這對展示和教學也非常有用。

**Independent Test**: 使用者點擊「載入範例資料」按鈕，系統立即載入 100 則範例留言，使用者可以立即開始編輯和匯出。

**Acceptance Scenarios**:

1. **Given** 使用者在空白首頁，**When** 點擊「載入範例資料」，**Then** 系統立即顯示 100 則範例留言在表格中（包含各種類型：正面、負面、詢問、表情符號）
2. **Given** 使用者已有資料，**When** 點擊「載入範例資料」，**Then** 系統詢問「這會清除當前資料，確定要繼續嗎？」並在確認後載入範例
3. **Given** 使用者載入範例資料後，**When** 進行編輯、新增欄位、匯出等操作，**Then** 所有功能正常運作，與真實資料無異

---

### User Story 3 - 線上編輯留言資料 (Priority: P3)

操作人員在匯入留言後，需要對資料進行清理、分類或標記，例如標示重要留言、刪除無關內容、新增分類標籤等，以便後續分析使用。

**為何優先**: 原始資料通常包含雜訊或需要分類，線上編輯功能讓使用者能立即處理資料，這是工具的核心價值。

**Independent Test**: 在完成 User Story 1 後，使用者可以對已匯入的留言進行編輯（修改內容、刪除列、新增標籤欄位），並確認編輯結果即時保存。

**Acceptance Scenarios**:

1. **Given** 已匯入的留言資料顯示在表格中，**When** 使用者雙擊任一留言的儲存格並修改內容，**Then** 系統即時更新該列資料並顯示「已儲存」提示
2. **Given** 表格中顯示多筆留言，**When** 使用者勾選特定留言列並點擊「刪除選取項目」，**Then** 系統顯示確認對話框「確定要刪除 N 筆留言？」，確認後移除選取的留言
3. **Given** 使用者在表格中，**When** 點擊「新增欄位」並輸入欄位名稱「客戶類型」，**Then** 系統在表格最右側新增一個可編輯的欄位，所有留言該欄位預設為空白
4. **Given** 使用者已對留言進行多次編輯，**When** 不小心誤刪重要留言，**Then** 可以點擊「復原」按鈕恢復最近一次的操作（支援至多 10 步復原）
5. **Given** 表格中有大量留言資料，**When** 使用者在搜尋框輸入關鍵字，**Then** 表格即時篩選並只顯示內容包含該關鍵字的留言

---

### User Story 4 - 匯出為 Excel 檔案 (Priority: P4)

操作人員完成資料清理後，需要將最終資料匯出為 Excel 檔案，以便在本地進行進階分析、製作報表，或與團隊分享資料。

**為何優先**: Excel 是商業環境中最通用的資料分析工具，匯出功能讓使用者能將資料整合到現有的工作流程中。

**Independent Test**: 使用者可以點擊「匯出 Excel」按鈕，下載包含所有留言資料（包括編輯後的內容和自訂欄位）的 .xlsx 檔案，並能在 Excel 中正常開啟查看。

**Acceptance Scenarios**:

1. **Given** 表格中有已匯入和編輯的留言資料，**When** 使用者點擊「匯出 Excel」按鈕，**Then** 瀏覽器自動下載一個命名為「留言資料_日期時間.xlsx」的檔案
2. **Given** 下載的 Excel 檔案，**When** 使用者在 Excel 中開啟，**Then** 所有欄位（留言者、內容、時間、自訂欄位等）正確對應，中文內容顯示正常無亂碼
3. **Given** 表格中有超過 1000 筆留言，**When** 執行匯出操作，**Then** 系統顯示「正在產生檔案...」進度提示，並在 5 秒內完成下載
4. **Given** 使用者已套用篩選條件（例如只顯示特定關鍵字的留言），**When** 點擊「匯出 Excel」，**Then** 系統詢問「要匯出全部資料還是僅匯出篩選後的資料？」並根據選擇執行

---

### Edge Cases

- **大型檔案上傳**: 當使用者上傳超過 10,000 則留言的檔案時，系統應顯示警告「此檔案包含大量資料，可能需要較長處理時間，是否繼續？」並分批顯示進度
- **檔案編碼問題**: 若 CSV 檔案使用非 UTF-8 編碼導致中文亂碼，系統應自動偵測並嘗試多種編碼（UTF-8, Big5, GBK），或提示使用者「偵測到編碼問題，請將檔案另存為 UTF-8 編碼」
- **欄位對應不確定**: 當檔案欄位名稱與預期不符（例如：「評論」vs「留言內容」），系統應提供欄位對應介面，讓使用者手動指定哪一欄是留言內容、哪一欄是留言者
- **重複匯入**: 使用者可能誤上傳相同檔案多次，系統應詢問「已有 X 則留言，要清除舊資料還是合併？」
- **特殊字元和表情符號**: 留言內容包含 emoji、特殊符號、換行符號時，應正確解析、顯示和匯出
- **日期格式多樣性**: 支援多種日期格式（YYYY-MM-DD、DD/MM/YYYY、timestamp）並自動解析轉換為統一格式
- **瀏覽器儲存配額**: 當 IndexedDB 使用量達到 80% 配額時，系統顯示警告並提供清理工具（與原版相同）
- **資料驗證**: 匯入時自動檢查必要欄位（留言內容不可為空），跳過無效列並記錄「已匯入 X 則，跳過 Y 則無效資料」

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須支援上傳 CSV、Excel (.xlsx) 和 JSON 格式的檔案
- **FR-002**: 系統必須提供「手動貼上」功能，讓使用者直接貼上 JSON 或 CSV 格式的文字資料
- **FR-003**: 系統必須提供「載入範例資料」功能，預載 100 則範例留言供體驗
- **FR-004**: 系統必須自動偵測和解析檔案格式（CSV、Excel、JSON）
- **FR-005**: 系統必須在檔案欄位名稱不明確時，提供欄位對應介面讓使用者手動指定
- **FR-006**: 系統必須驗證匯入資料的必要欄位（留言內容必填），跳過無效資料並顯示匯入摘要
- **FR-007**: 系統必須在匯入過程中顯示進度指示器（正在解析、已匯入 X 則）
- **FR-008**: 系統必須將匯入的留言資料以表格形式呈現，並提供排序功能（按時間、按讚數等）
- **FR-009**: 使用者必須能在線上編輯表格中的任何儲存格內容
- **FR-010**: 使用者必須能勾選並刪除多筆留言記錄
- **FR-011**: 系統必須支援新增自訂欄位（例如：客戶類型、回應狀態、優先等級），所有自訂欄位均為純文字類型
- **FR-012**: 系統必須提供搜尋和篩選功能，讓使用者快速找到特定留言
- **FR-013**: 系統必須支援復原（Undo）功能，至少保留最近 10 次操作記錄
- **FR-014**: 系統必須能將表格資料匯出為 .xlsx 格式的 Excel 檔案
- **FR-015**: 匯出的 Excel 檔案必須包含所有可見欄位（原始欄位和自訂欄位），且中文內容無亂碼
- **FR-016**: 系統必須處理匯入錯誤（檔案格式錯誤、編碼問題、欄位缺失）並顯示友善的錯誤訊息
- **FR-017**: 所有 UI 文字、按鈕標籤、錯誤訊息必須使用繁體中文
- **FR-018**: 系統必須記錄使用者最近匯入的檔案名稱，方便追蹤資料來源
- **FR-019**: 系統必須監控 IndexedDB 儲存配額使用量，當達到 80% 時顯示警告並提供清理工具
- **FR-020**: 系統必須支援多種日期格式並自動解析轉換為統一格式（YYYY-MM-DD HH:mm）
- **FR-021**: 系統必須支援批次匯入多個檔案，並在表格中標註資料來源檔案名稱

### Key Entities

- **匯入批次 (Import Batch)**: 代表單次匯入操作，屬性包括：批次 ID、檔案名稱、匯入時間、總留言數、成功數量、失敗數量
- **留言 (Comment)**: 代表單一留言，屬性包括：留言 ID、留言者名稱、留言內容、留言時間、按讚數、回覆數、來源檔案、自訂欄位
- **自訂欄位 (Custom Field)**: 使用者新增的額外欄位，屬性包括：欄位名稱、欄位值（純文字）
- **操作歷史 (Operation History)**: 記錄使用者的編輯操作以支援復原功能，屬性包括：操作類型（編輯/刪除/新增）、操作時間、受影響的資料
- **儲存配額狀態 (Storage Quota Status)**: 追蹤 IndexedDB 使用量，用於觸發警告

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者從上傳檔案到看到留言顯示的時間在 5 秒內（針對少於 1,000 則留言的檔案）
- **SC-002**: 系統能成功解析並匯入至少 95% 的有效留言資料（格式正確的資料）
- **SC-003**: 90% 的使用者能在 2 分鐘內完成首次匯入任務（包括上傳檔案、查看結果）
- **SC-004**: 匯出的 Excel 檔案在常見的 Excel 軟體中開啟時，100% 的中文內容正確顯示無亂碼
- **SC-005**: 系統在處理包含 1,000 則留言的檔案時，匯入時間不超過 3 秒，編輯操作回應時間不超過 100 毫秒
- **SC-006**: 支援至少 3 種檔案格式（CSV、Excel、JSON），並正確解析各種常見的欄位名稱（留言/評論/comment、留言者/使用者/user）
- **SC-007**: 使用者首次使用時，95% 能在無需查看說明文件的情況下完成基本匯入和匯出操作
- **SC-008**: 錯誤情況發生時，100% 的錯誤訊息必須清楚說明問題原因和建議解決方式

### Constitution Compliance *(mandatory)*

**Per Constitution Principles**:

- **Code Quality**: 
  - 程式碼覆蓋率目標：80% 最低要求，檔案解析和資料處理模組達到 100%

  - 複雜度 (cyclomatic complexity) 不得超過 10

    - **整合測試 (Integration Tests)**: 端到端的匯入、編輯、匯出流程
    - **效能測試 (Performance Tests)**: 大量資料（1000+ 則）的處理效能

- **UX Consistency**:

  - 顯示載入指示器：所有超過 300ms 的操作（檔案解析、匯出）

  - 錯誤訊息：必須使用繁體中文、說明問題原因、提供解決建議

- **Performance Requirements**:
  - 頁面初次載入時間：<2 秒（3G 網路環境）

  - 記憶體使用：處理 10,000 則留言時瀏覽器記憶體使用不超過 500MB

  - ✅ 本規格書使用繁體中文撰寫
  - ✅ 所有使用者故事使用繁體中文
  - ✅ 所有 UI 文字必須使用繁體中文
  - ✅ 錯誤訊息必須使用繁體中文並提供明確的指引

## 假設與限制

### 假設 (Assumptions)

1. **資料來源**: 假設使用者能透過其他方式（手動複製、第三方工具、CSV 匯出等）取得留言資料。系統不負責資料收集，僅提供資料整理和分析功能
2. **系統架構**: 系統採用純前端單頁應用（SPA）架構，無需後端伺服器。所有處理都在瀏覽器中完成，確保最佳隱私保護
3. **檔案大小**: 假設使用者上傳的檔案大小在合理範圍內（建議 <10MB，約 20,000 則留言），超大檔案可能影響瀏覽器效能
4. **瀏覽器支援**: 假設使用者使用現代瀏覽器（Chrome 90+, Edge 90+, Firefox 88+, Safari 14+），支援 File API、IndexedDB、ES6+ 等現代 Web 標準
5. **資料儲存方式**: 系統採用瀏覽器端儲存架構，使用 IndexedDB 作為主要儲存機制。資料保留在使用者本地裝置，預設保留 30 天或直到使用者手動清除
6. **檔案格式**: 假設使用者提供的檔案格式符合常見標準（CSV 逗號分隔、Excel 標準格式、JSON 標準語法）
7. **語言環境**: 假設目標使用者為繁體中文使用者，系統介面和錯誤訊息以繁體中文為主

### 限制 (Constraints)

1. **無自動爬取**: 系統不提供自動爬取社群平台的功能，使用者需自行準備留言資料檔案
2. **瀏覽器儲存配額**: IndexedDB 儲存空間受瀏覽器和裝置限制（通常數 GB），達到配額上限時系統功能受限，使用者需定期清理舊資料
3. **匯出檔案大小**: Excel 檔案匯出受限於瀏覽器記憶體，建議單次匯出不超過 50,000 則留言（約 50MB）
4. **檔案解析限制**: 非常複雜或非標準格式的檔案可能無法正確解析，建議使用者使用標準格式
5. **離線限制**: 由於是純前端應用，首次載入後可離線使用，但初次載入需要網路連線
6. **跨裝置同步**: 資料儲存在瀏覽器本地，無法跨裝置同步，使用者需手動匯出和匯入資料
7. **法律合規**: 使用者自行負責確保資料來源合法，系統僅提供資料處理工具

## 附錄

### 支援的檔案格式範例

#### CSV 格式範例

```csv
留言者,留言內容,留言時間,按讚數,回覆數
王小明,這個產品很不錯,2025-11-18 10:30,5,2
李小華,非常滿意,2025-11-18 11:00,3,1
張大明,品質很好,2025-11-18 12:00,8,0
```

**欄位名稱支援（自動辨識）**:
- 留言者：commenter, user, username, name, 留言者, 使用者, 姓名
- 留言內容：content, message, text, comment, 留言, 內容, 評論
- 時間：time, timestamp, date, created_time, 時間, 日期
- 按讚數：likes, like_count, 按讚, 讚
- 回覆數：replies, reply_count, comment_count, 回覆

#### JSON 格式範例

```json
[
  {
    "commenter": "王小明",
    "content": "這個產品很不錯",
    "timestamp": "2025-11-18 10:30",
    "likes": 5,
    "replies": 2
  }
]
```

#### Excel 格式

- 第一列為標題列（欄位名稱）
- 支援 .xlsx 格式
- 自動偵測欄位對應
