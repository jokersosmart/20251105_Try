# 功能規格書：通用留言擷取工具

**Feature Branch**: `003-universal-comment-scraper`  
**Created**: 2025-11-20  
**Status**: Draft  
**最終目標**: Chrome 瀏覽器擴充套件

## 專案願景

建立一個通用的留言擷取工具，能自動識別並擷取多個社群平台和部落格平台的留言內容。工具智能判斷平台類型，自動選擇最佳擷取方式（API、網頁爬蟲、或模擬登入），讓使用者只需提供網址（必要時提供API或帳密），即可取得留言者資訊、留言內容、時間戳記等完整資料，並支援即時顯示或匯出Excel。

**支援平台**：
- 社群媒體：Facebook、Instagram、Threads
- 內容平台：方格子、痞客邦
- 國際平台：Medium、Substack  
- 通用：任何具有留言功能的部落格或網站

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 智能平台識別與擷取設定 (Priority: P1) 🎯 MVP

使用者在工具中輸入任何網址，系統自動識別平台類型（Facebook、Instagram、部落格等），判斷該平台需要何種認證方式（無需認證、API Key、或帳號密碼），並引導使用者提供必要資訊，完成擷取前的準備工作。

**為何優先**: 平台識別和認證設定是所有擷取功能的基礎，沒有這個核心功能就無法進行後續資料擷取。智能識別降低使用門檻，使用者不需要知道技術細節。

**Independent Test**: 使用者輸入不同平台的網址（例如Facebook貼文、Medium文章、方格子文章），系統能正確識別平台並顯示對應的認證需求提示。

**Acceptance Scenarios**:

1. **Given** 使用者在首頁，**When** 輸入Facebook貼文網址並點擊「開始擷取」，**Then** 系統識別為Facebook平台，提示「此平台需要API Token或帳號登入」並顯示兩個選項「使用API Token」和「使用帳號登入」
2. **Given** 使用者選擇「使用API Token」，**When** 輸入Token並點擊「驗證」，**Then** 系統驗證Token有效性，顯示「✅ Token驗證成功，可以開始擷取」或「❌ Token無效，請檢查」
3. **Given** 使用者選擇「使用帳號登入」，**When** 輸入帳號密碼，**Then** 系統模擬登入，驗證成功後提示「✅ 登入成功」
4. **Given** 使用者輸入Medium文章網址，**When** 點擊「開始擷取」，**Then** 系統識別為Medium平台，提示「此平台可直接擷取公開留言，無需認證」並直接進入擷取流程
5. **Given** 使用者輸入無法識別的網址，**When** 系統無法判斷平台類型，**Then** 顯示「無法自動識別平台類型，請選擇通用爬蟲模式」並提供手動配置選項

### User Story 2 - 多平台留言擷取執行 (Priority: P2)

使用者完成認證設定後，系統根據平台類型使用對應的擷取方式（API呼叫、網頁解析、或模擬操作），自動取得指定網址的所有留言，包括留言內容、留言者姓名或帳號、留言時間、互動數據（按讚、回覆數），並顯示即時進度。

**為何優先**: 這是核心功能，實際執行資料擷取。支援多種平台和擷取方式是工具的核心價值。

**Independent Test**: 使用者提供Facebook貼文網址和有效Token，系統能成功擷取所有留言並顯示在介面上，包含留言者、內容、時間。

**Acceptance Scenarios**:

1. **Given** 使用者已設定Facebook API Token，**When** 輸入貼文網址並點擊「開始擷取」，**Then** 系統顯示進度「正在擷取... 已取得 X 則留言」，完成後顯示所有留言列表
2. **Given** 使用者輸入方格子文章網址（無需認證），**When** 點擊「開始擷取」，**Then** 系統自動解析網頁HTML，提取所有留言內容和留言者暱稱，顯示進度並完成
3. **Given** 系統正在擷取留言，**When** 擷取過程中發生錯誤（網路中斷、API速率限制、權限不足），**Then** 顯示明確錯誤訊息「發生錯誤：[具體原因]，已保存 X 則留言」並提供重試選項
4. **Given** 使用者輸入包含分頁的留言列表，**When** 系統偵測到有更多留言需要載入，**Then** 自動處理分頁，顯示「正在載入第2頁...」直到取得所有留言
5. **Given** 使用者選擇「批次模式」並輸入多個網址，**When** 點擊「批次擷取」，**Then** 系統依序處理每個網址，顯示總體進度「處理第2/5個網址...」，完成後整合所有留言

### User Story 3 - 留言資料顯示與即時查看 (Priority: P3)

擷取完成後，系統以清晰的表格或卡片方式顯示所有留言資料，使用者可以即時查看留言內容、留言者資訊、時間戳記，並支援搜尋、篩選、排序功能，方便快速找到特定留言。

**為何優先**: 即時顯示讓使用者能立即查看擷取結果，確認資料正確性，並進行初步分析，無需匯出即可使用。

**Independent Test**: 擷取完成後，使用者能在介面上看到所有留言，可以搜尋關鍵字篩選留言，可以按時間或按讚數排序。

**Acceptance Scenarios**:

1. **Given** 留言擷取完成，**When** 查看結果頁面，**Then** 所有留言以清晰的列表顯示，每則留言包含：留言者、內容、時間、按讚數、來源（哪個貼文或文章）
2. **Given** 顯示的留言列表，**When** 使用者在搜尋框輸入關鍵字「很棒」，**Then** 表格即時篩選，只顯示內容包含「很棒」的留言
3. **Given** 留言列表顯示中，**When** 使用者點擊「時間」欄位標題，**Then** 留言按時間順序重新排序（最新或最舊）
4. **Given** 使用者查看留言，**When** 點擊任一留言者姓名，**Then** 顯示該留言者的所有留言（篩選同一人）
5. **Given** 顯示大量留言（>1000則），**When** 使用者滾動列表，**Then** 使用虛擬滾動技術，保持頁面流暢，記憶體使用<500MB

### User Story 4 - 資料匯出與格式化 (Priority: P4)

使用者可以選擇將擷取的留言資料匯出為Excel檔案，系統自動格式化資料（統一時間格式、清理特殊字元、整理欄位），確保匯出的檔案可以在Excel中正常開啟，繁體中文無亂碼，欄位清楚對應。

**為何優先**: Excel匯出是資料分析的重要環節，讓使用者能將資料整合到現有工作流程，進行進階分析或報表製作。

**Independent Test**: 使用者點擊「匯出Excel」，下載檔案後在Excel中開啟，所有留言資料完整，中文正常顯示，欄位有明確標題。

**Acceptance Scenarios**:

1. **Given** 留言資料已擷取，**When** 使用者點擊「📥 匯出Excel」，**Then** 瀏覽器自動下載檔案「留言資料_平台名稱_日期時間.xlsx」
2. **Given** 下載的Excel檔案，**When** 在Microsoft Excel中開啟，**Then** 所有欄位正確對應（留言者、內容、時間、按讚數、來源），繁體中文、emoji、特殊符號正常顯示
3. **Given** 擷取了來自多個平台的留言，**When** 匯出Excel，**Then** 每則留言額外包含「平台」欄位（Facebook、Medium等），方便分類分析
4. **Given** 使用者已套用篩選或搜尋，**When** 點擊「匯出」，**Then** 系統詢問「匯出全部資料還是僅匯出篩選後的資料？」並按選擇執行

### User Story 5 - Chrome擴充套件整合 (Priority: P5)

使用者安裝Chrome擴充套件後，在瀏覽任何支援的平台時，擴充套件圖示會亮起，點擊圖示即可在當前頁面直接擷取留言，無需複製網址到另一個網站，提供最流暢的使用體驗。

**為何優先**: Chrome擴充套件是最終目標，提供最佳使用者體驗，但需要在網頁版本穩定後才開發。

**Independent Test**: 使用者在Facebook貼文頁面，點擊擴充套件圖示，彈出小視窗顯示擷取進度，完成後可直接查看留言或下載。

**Acceptance Scenarios**:

1. **Given** 使用者安裝擴充套件並瀏覽Facebook貼文，**When** 點擊瀏覽器右上角的擴充套件圖示，**Then** 彈出小視窗，顯示「偵測到Facebook貼文，是否擷取留言？」並有「開始擷取」按鈕
2. **Given** 擴充套件偵測到當前頁面為支援的平台，**When** 圖示變為彩色（啟用狀態），**Then** 使用者知道此頁面可以擷取留言
3. **Given** 使用者在不支援的網站，**When** 擴充套件圖示保持灰色，**Then** 點擊後顯示「當前頁面不支援自動擷取，請使用通用模式」

### Edge Cases

- **API速率限制**: 當Facebook或Instagram達到API速率限制時，系統顯示「API配額已達上限，建議X分鐘後再試」，並支援切換為模擬登入模式繼續擷取
- **需要登入的內容**: 當目標內容需要登入才能查看時，系統提示「此內容需要登入」，引導使用者選擇「提供帳號密碼」或「手動複製」
- **動態載入留言**: 某些平台的留言需要滾動才會載入更多，系統自動模擬滾動行為，確保取得所有留言
- **多種留言格式**: 不同平台的留言可能包含文字、圖片、連結、emoji，系統能正確提取純文字內容並保留emoji
- **網頁結構變更**: 當平台更新網頁結構導致爬蟲失效時，系統顯示「該平台結構已變更，請更新工具」並提供反饋機制
- **大量留言處理**: 當貼文有超過5,000則留言時，系統詢問「此貼文有大量留言，是否繼續？預估時間X分鐘」
- **隱私內容**: 當內容為私人或僅限特定群組可見時，系統顯示「無權存取此內容」
- **特殊字元處理**: 留言包含HTML標籤、特殊符號、不同語言文字時，正確解析和清理
- **平台偵測失敗**: 當無法自動識別平台時，提供「通用模式」，讓使用者手動配置留言選擇器（CSS Selector）
- **跨平台資料整合**: 當使用者擷取來自多個不同平台的留言時，統一資料格式，標註來源平台

## Requirements *(mandatory)*

### Functional Requirements

**核心功能**:
- **FR-001**: 系統必須支援輸入任何網址（文章、貼文、影片等含留言的頁面）
- **FR-002**: 系統必須自動識別網址所屬平台（Facebook、Instagram、Threads、方格子、痞客邦、Medium、Substack、或通用部落格）
- **FR-003**: 系統必須智能判斷該平台所需的認證方式：無需認證、API Token、或帳號密碼
- **FR-004**: 系統必須支援三種擷取模式：API模式（使用官方API）、爬蟲模式（解析網頁）、模擬模式（模擬使用者操作）
- **FR-005**: 系統必須根據平台自動選擇最佳擷取模式，並在該模式失敗時提供替代方案

**認證管理**:
- **FR-006**: 系統必須提供Token管理介面，讓使用者輸入和儲存多個平台的API Token
- **FR-007**: 系統必須驗證Token有效性，並顯示Token狀態（有效、過期、權限不足）
- **FR-008**: 系統必須支援帳號密碼模式，安全地儲存憑證（加密），並在需要時自動使用
- **FR-009**: 系統必須在模擬登入模式下，模擬真實使用者行為（包括滾動、點擊載入更多等），避免被偵測為機器人

**留言擷取**:
- **FR-010**: 系統必須擷取留言的核心資訊：留言內容（文字）、留言者姓名或帳號、留言時間、互動數據（按讚、回覆數）
- **FR-011**: 系統必須在擷取過程中顯示即時進度（已擷取X則、預估剩餘時間、當前處理狀態）
- **FR-012**: 系統必須支援批次擷取，允許使用者一次輸入多個網址或指定整個帳號/專頁
- **FR-013**: 系統必須處理分頁和動態載入，確保取得所有留言而非僅首頁可見的部分
- **FR-014**: 系統必須處理各平台的速率限制和反爬蟲機制，實作適當的延遲和重試策略

**資料處理**:
- **FR-015**: 系統必須將擷取的留言以表格方式即時顯示，支援搜尋、篩選、排序功能
- **FR-016**: 系統必須支援匯出為Excel檔案，包含所有欄位，繁體中文無亂碼
- **FR-017**: 系統必須統一不同平台的資料格式（時間格式標準化、欄位名稱一致）
- **FR-018**: 系統必須在每則留言標註來源（平台名稱、原始網址、擷取時間）

**擴充套件功能**:
- **FR-019**: Chrome擴充套件必須偵測當前頁面是否為支援的平台，自動啟用圖示
- **FR-020**: 擴充套件必須提供右鍵選單，讓使用者在任何留言區域右鍵點擊「擷取此頁面留言」
- **FR-021**: 擴充套件必須在背景執行擷取，不阻擋使用者瀏覽其他頁面

**通用需求**:
- **FR-022**: 所有UI文字、錯誤訊息必須使用繁體中文
- **FR-023**: 系統必須記錄擷取歷史，包括網址、擷取時間、留言數量
- **FR-024**: 系統必須提供資料本地儲存（IndexedDB），並在達到80%配額時警告

### Key Entities

- **平台配置 (Platform Config)**: 定義每個支援平台的特性，屬性包括：平台名稱、識別規則（網址pattern）、認證類型（none/api/login）、擷取模式（api/scrape/simulate）、留言選擇器（CSS/API endpoint）
- **擷取任務 (Scrape Task)**: 代表單次擷取操作，屬性包括：任務ID、目標網址、平台類型、認證方式、狀態（pending/running/completed/failed）、進度、結果摘要
- **留言 (Comment)**: 統一的留言資料結構，屬性包括：留言ID、平台、留言者、留言內容、時間、按讚數、回覆數、來源網址、擷取時間
- **認證憑證 (Credentials)**: 儲存的認證資訊，屬性包括：平台、類型（api/login）、Token或加密的帳密、有效期、最後驗證時間
- **擷取歷史 (Scrape History)**: 記錄所有擷取操作，屬性包括：時間、網址、平台、成功數量、失敗原因

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者從輸入網址到開始擷取的時間在30秒內（包含平台識別和認證）
- **SC-002**: 系統能正確識別至少90%的常見平台網址（Facebook、Instagram、Medium等）
- **SC-003**: 對於公開留言（無需認證），擷取成功率達95%以上
- **SC-004**: 使用API模式時，擷取速度為每秒至少10則留言
- **SC-005**: 使用爬蟲模式時，擷取1000則留言的時間不超過5分鐘
- **SC-006**: 匯出的Excel檔案在各種Excel軟體中開啟，100%繁體中文、emoji正確顯示
- **SC-007**: Chrome擴充套件從點擊到顯示結果，完整流程在2分鐘內完成（針對100則留言的頁面）
- **SC-008**: 支援至少5個主要平台（Facebook、Instagram、Medium、方格子、痞客邦），每個平台擷取成功率>90%

**Per Constitution Principles**:

  - 程式碼覆蓋率目標：80%最低，擷取核心邏輯100%
  - 每個平台擷取器獨立模組，複雜度<10

- **Testing Standards**: 
  - 單元測試：每個平台解析器獨立測試
  - 整合測試：端到端擷取流程測試
  - 效能測試：大量留言處理測試

  - 擷取進度即時更新：每秒至少一次
  - 錯誤訊息：繁體中文、說明原因、提供解決方案

- **Performance Requirements**:
  - 工具載入時間：<2秒
  - 單則留言處理時間：<100ms
  - 支援處理10,000則留言不崩潰

  - 所有UI和文件使用繁體中文
  - 錯誤訊息提供具體指引

## 假設與限制

### 假設 (Assumptions)

1. **MVP平台範圍**: 初期版本優先支援Facebook和Instagram（使用官方Graph API），其他平台在後續版本加入。選擇這兩個平台因為已有完整API研究、使用者需求明確、且完全合法合規
2. **認證方式**: 優先實作API模式（使用官方API Token），網頁爬蟲作為備案，模擬登入僅在必要時謹慎使用（考慮法律風險）
3. **產品形態**: 先開發網頁版本（React SPA），驗證核心功能和使用者價值後，再開發Chrome擴充套件（預計V2階段）
4. **資料儲存**: 使用IndexedDB本地儲存，資料不外傳，保護使用者隱私，支援離線查看已擷取的留言
5. **開發優先順序**: MVP專注於Facebook/Instagram的API擷取、基本顯示和Excel匯出功能，預計4週完成。平台擴充和進階功能在後續迭代
6. **平台穩定性**: 假設各平台的API和網頁結構相對穩定，重大改版時需要維護更新
7. **網路環境**: 假設使用者具備穩定網路連線（至少3G/4G）
8. **瀏覽器支援**: 假設使用者使用現代瀏覽器（Chrome 90+, Edge 90+, Firefox 88+）
9. **合法使用**: 假設使用者用於合法的內容分析、研究或個人資料整理用途，遵守各平台服務條款
10. **使用者技術能力**: 假設使用者能取得並輸入API Token（提供詳細指引），或接受手動複製的替代方案

### 限制 (Constraints)

1. **法律風險**: 網頁爬蟲可能違反某些平台的服務條款，使用者需自行承擔風險
2. **反爬蟲機制**: 部分平台有嚴格的反爬蟲措施，可能導致IP封鎖或帳號限制
3. **動態內容**: JavaScript渲染的動態內容需要完整瀏覽器環境，增加複雜度
4. **帳密安全**: 儲存使用者帳密有安全風險，需要謹慎處理
5. **維護成本**: 支援多平台意味著每個平台更新都可能需要維護
6. **API配額**: 使用官方API時受配額限制
7. **擴充套件審查**: Chrome Web Store對擴充套件有審查要求，某些功能可能不被允許
